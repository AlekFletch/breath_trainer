# Дыхательный тренажёр для HUAWEI WATCH FIT 4 Pro — план

> Статус на 2026-09-12: план утверждён, разработка начинается завтра.
> Код ещё не писался. Первым делом — этап 0.

## Контекст

Во встроенном «Дыхательном упражнении» Huawei настраиваются только длительность и «темп» (медленный/средний/быстрый) — задать свои четыре фазы по секундам нельзя. Нужно своё приложение на часах: **вдох → задержка → выдох → задержка**, каждая фаза в секундах, плюс общее время сессии. На экране шарик: растёт на вдохе, пульсирует в такт секундам на верхней задержке, уменьшается на выдохе, пульсирует уменьшенным на нижней задержке.

Решения пользователя: телефон — **не-Huawei Android**; цель — **для себя**, но код готовим так, чтобы публикация была возможна; порядок — **сначала проверка установки**; функции — вибрация, настройка на часах, пресеты, счётчик и прогресс.

## Техническая база (проверено)

| Факт | Значение | Последствие |
|---|---|---|
| Класс устройства | Lite Wearable (LiteOS под HarmonyOS 5.1) | ArkTS **не поддерживается** |
| Язык / фреймворк | JS + HML + CSS (ArkUI.Lite, «как мини-программа») | Код близок к вебу → прототип переносится почти 1:1 |
| Экран | 480 × 408, AMOLED, прямоугольный | Шарик до ~340 px, поля 34 px |
| Доступные API | CSS-анимации, `setInterval`, вибрация, яркость, датчики, хранилище, колесо/кнопка «назад» | Всё нужное есть |
| IDE | DevEco Studio, шаблон **Lite Wearable / Lite Empty Ability** (не ArkTS) | Ставится на Windows |
| Установка на часы | сборка → файл на телефон в `/sdcard/haps/` → приложение **«应用调测助手» / DevEco Assistant** (`com.huawei.deveco.assistant`) + Huawei Health по Bluetooth → «Установить приложение на часы» | Телефон — обязательное звено |
| Подпись | Key + CSR из DevEco Studio → AppGallery Connect → debug-сертификат + профиль, UDID часов берётся в DevEco Assistant | Нужен аккаунт разработчика Huawei |
| Белый список / заявка в Huawei | Для базовой Lite Wearable разработки не требуется | Порог входа — только аккаунт |

Магазин приложений для часов на Fit 4 Pro есть (AppGallery внутри Huawei Health), так что путь к публикации открыт — но на этом этапе не используется.

## Архитектура

Ядро вынесено в чистый модуль без привязки к платформе — один и тот же файл работает и в браузерном прототипе, и на часах.

```
src/
  core/
    engine.js       # конечный автомат сессии: фазы, тики, завершение. Без DOM, без таймеров платформы.
    presets.js      # 4-7-8, квадрат 4-4-4-4, расслабление 4-0-6-0, «Своё»
  platform/
    web.js          # адаптер для браузера: vibrate → лог, keepScreenOn → no-op
    lite.js         # адаптер для часов: @system.vibrator, @system.brightness, @system.storage
prototype/          # HTML-страница 480×408 для отладки в браузере
watch/              # проект DevEco Studio (Lite Wearable)
  entry/src/main/js/default/
    app.js
    pages/
      index/        # главный экран: пресеты + Старт
      session/      # шарик, фаза, счётчик, прогресс
      settings/     # 5 значений: вдох / задержка / выдох / задержка / сессия
```

**`engine.js` — центральное решение.** Автомат управляется абсолютным временем (`Date.now()`), а не накоплением интервалов: `setInterval` на часах даёт дрейф, и за 10-минутную сессию расхождение станет заметным. Наружу отдаёт на каждом тике объект `{phase, phaseElapsed, phaseDuration, progress01, cycleIndex, sessionLeft}` — рендер просто отображает это состояние и не хранит своего.

Фаза с длительностью `0` пропускается — так пресет «4-0-6-0» работает без ветвлений в UI.

Помимо состояния движок отдаёт дискретные события: `phaseStart(phase)` и `secondTick(n)` (пересечение границы секунды внутри фазы). Рисунок вибрации строится на них, а не на состоянии, — иначе при подвисании кадра импульс либо потеряется, либо задвоится. Решение «вибрировать или нет» принимает адаптер платформы, движок про вибрацию ничего не знает.

## Поведение шарика

| Фаза | Анимация |
|---|---|
| Вдох | scale 0.45 → 1.0 за N секунд, плавное замедление к концу |
| Задержка вверху | пульсация вокруг 1.0 с амплитудой ±4 %, ровно один такт в секунду |
| Выдох | scale 1.0 → 0.45 |
| Задержка внизу | пульсация вокруг 0.45, ±4 %, такт в секунду |

Реализация на часах: CSS `transform: scale()` + анимация. Если ArkUI.Lite не потянет плавность — запасной вариант: покадровое изменение `width`/`height` у `div` с `border-radius: 50%` по `setInterval` 20–25 fps. Какой путь рабочий, определяется на этапе 3 на реальном железе.

## Вибрация

Вибрация — основной канал: по ней можно заниматься с закрытыми глазами, вообще не глядя на экран. Рисунок по фазам:

| Фаза | Вибрация |
|---|---|
| Вдох | идёт **всю фазу** — частая череда коротких импульсов, «бум-бум-бум-бум-бум» |
| Задержка после вдоха | одиночный тик на каждой секунде: 1-я, 2-я, 3-я, 4-я… |
| Выдох | **тишина** |
| Задержка после выдоха | одиночный тик на каждой секунде |

Тишина на выдохе — часть рисунка, а не упущение: на контрасте с непрерывной вибрацией вдоха выдох опознаётся однозначно, и все четыре фазы различаются на ощупь без экрана.

Реализация: `@system.vibrator` на Lite Wearable даёт, судя по документации, только режимы `short` / `long` — то есть «непрерывная» вибрация вдоха собирается из частых коротких импульсов по таймеру. Частота выносится в параметр `inhalePulseHz`, по умолчанию ~3 импульса в секунду, подбирается на живом устройстве на этапе 3. Если окажется, что доступна длительная вибрация на заданное время — вдох переводится на неё, это и дешевле по батарее, и ровнее на ощупь.

Тики задержек привязываются к тем же границам секунд, что и пульсация шарика, — вибрация и анимация должны совпадать, а не расходиться на доли секунды.

В настройках — выключатель вибрации.

## Этапы

### Этап 0 — проверка установки (блокирующий, делается первым)

Смысл: до того, как писать приложение, убедиться, что собранный пакет вообще встаёт на конкретные часы с конкретного телефона. Проверяется пустым «Hello World».

Действия пользователя:
1. Регистрация аккаунта разработчика Huawei (developer.huawei.com), верификация личности.
2. Установка DevEco Studio на Windows.
3. На Android-телефоне: Huawei Health (уже есть, раз часы работают) + **应用调测助手 / DevEco Assistant** — APK из AppGallery или из стора Tencent (`com.huawei.deveco.assistant`).
4. В DevEco Assistant при подключённых по Bluetooth часах — посмотреть, что часы видны, и скопировать **UDID**.

Действия со стороны Claude:
5. Создать проект по шаблону Lite Wearable, собрать минимальный пакет.
6. Пошаговая инструкция по сертификатам: Build → Generate Key and CSR → AppGallery Connect → Certificate Management → debug-сертификат → регистрация UDID часов → профиль → подпись сборки.
7. Пакет кладётся на телефон в `/sdcard/haps/`, ставится через DevEco Assistant.

**Критерий прохождения:** на часах появилась иконка приложения, оно открывается и показывает текст. Пока этого нет, к этапам 1–3 переходить незачем.

Если этап 0 не проходит — разбираем причину по конкретной ошибке (чаще всего: непринятый UDID, просроченный профиль, DevEco Assistant не видит часы через не-Huawei телефон). Запасной вариант на случай, если DevEco Assistant не работает с этим телефоном: одолжить любой Huawei-телефон только на время установки — приложение после установки живёт на часах самостоятельно.

### Этап 1 — движок и прототип в браузере

- `engine.js` + `presets.js` с покрытием тестами: длительности фаз, пропуск нулевых фаз, завершение сессии по общему времени, отсутствие дрейфа на длинной сессии, пауза/возобновление.
- HTML-прототип 480 × 408 — точный размер экрана часов — с шариком, фазой, счётчиком и прогрессом. На нём подбираются ощущения: кривая роста, амплитуда пульсации, читаемость цифр.

### Этап 2 — перенос в проект Lite Wearable

Разметка переводится HTML → HML, стили остаются CSS (подмножество), логика — тот же `engine.js` плюс адаптер `lite.js`. Три экрана: главный, сессия, настройки. Настройки сохраняются через `@system.storage`, чтобы не задавать их заново при каждом запуске.

#### Выводы этапа 2 (2026-09-15)

Проверено по SDK 6.1.1 и сборкой:
- **Компоненты Lite Wearable** (из `ace-loader/lib/templater/lite_component_map.js`): div, stack, text, image, list / list-item, swiper, tabs, progress (horizontal / arc), switch, slider, input, picker-view, canvas, chart, marquee, image-animator, qrcode, analog-clock. События: click, longpress, swipe, touch*, key.
- **Привязка данных в `class` не поддерживается** (ошибка компиляции) — переключаемое оформление только через `style="…: {{…}}"`.
- **Навигация — только `router.replace`**, стека страниц нет (`router.back` помечен Full). Настройки передаются параметром перехода `settingsJson` и сохраняются в `@system.storage`.
- **Ловушка сборки:** корневой `package.json` с `"type": "module"` заставлял webpack из ace-loader считать страницы ES-модулями — импорты общего кода и `@babel/runtime` оставались «сырыми» `require` и на часах упали бы. Лечится `watch/entry/src/main/js/package.json` с `"type": "commonjs"`. Признак проблемы: страницы в `build/.../lite_source` по ~10 КБ без кода движка.
- **Имя `render` занято (2026-09-16):** сборщик пишет шаблон в `options.render` и затирает одноимённый метод страницы — подписи оставались пустыми, в Previewer был чёрный экран. Метод назван `refresh`, тест `watch-pages` следит.
- **Нет RegExp (2026-09-16):** JerryScript часов собран без регулярных выражений — один литерал `/[-_]/` в `i18n.js` не давал разобрать файл страницы целиком (`Eval JS file failed: TypeError: wrong type of argument`), Previewer показывал чёрный экран. Заменено на `split`, тест `watch-pages` запрещает регулярные выражения в коде часов.
- **Фокус колёсика и падение движка (2026-09-16):** список с `rotation({ focus: true })`, удалённый при `router.replace`, остаётся в рантайме висячей ссылкой — следующий поворот колёсика или касание роняют движок (`JsEngine Crash`, `0xc0000005`; в Previewer — «Preview failed»). Настройки и язык уходят только через `leave()`, который сначала снимает фокус (`focusRotation(list, false)`); тест `watch-pages` следит. Воспроизводилось стабильно: настройки → назад → поворот → касание; после правки — 24 цикла без падений.
- **`storage.get` без `default`** пишет `JSI:ValueToString params invalid!`, если ключа ещё нет, — `default: ''` передаётся всегда.
- **Отладка без IDE:** `sdk\default\hms\previewer\liteWearable\bin\Simulator.exe` запускается напрямую с аргументами, как у DevEco (команда видна в свойствах процесса; `-sid` — 32 hex-символа, `-j` — папка `build\...\loader_out_lite\default\js\MainAbility`). В stdout идут ошибки движка и `console.info` (`console.log` не выводится). Таймеры и колбэки работают, только пока подключён клиент кадров (WebSocket `ws://127.0.0.1:<lws>/<lws>/<sid>`). Касания и колёсико — JSON-команды `MousePress` / `MouseRelease` / `MouseMove` `{x, y}` и `CrownRotate` `{rotate}` в именованный канал `\\.\pipe\<-s>_commandPipe`, где симулятор — клиент. Запускать из временной папки: рядом с рабочей папкой он создаёт `file_system/` для хранилища.
- **Экран часов — 408 × 480 (вертикальный)**, а не 480 × 408: так видно по фото с часов. Вёрстка страниц `watch/` рассчитана на 408 × 480; браузерный прототип пока 480 × 408.
- **Симулятор без Studio, рабочие аргументы:** `-j <loader_out_lite/.../MainAbility> -s <имя> -n entry -device liteWearable -shape rect -or 408 480 -cr 408 480 -lws <порт> -sid <32 hex> -hs 102400 -url pages/index/index`; рядом с рабочей папкой нужен `config/` из `previewer/liteWearable/config` (шрифт), без `-device` симулятор падает. Канал команд должен быть в режиме сообщений (`CreateNamedPipe` с `PIPE_TYPE_MESSAGE`) — байтовый канал Node не подходит. Кадры в WebSocket — JPEG после заголовка (искать `FF D8 FF`).
- **Previewer Lite Wearable** — круглый экран 454×454 (`liteWearableSettingConfig.json`), не 480×408: вёрстка в нём обрезается, это не ошибка.
- **Общий код в страницы — копией** `src/core` в `common/` (`npm run sync:watch`), тест следит за расхождением.
- **Звука нет**: аудио-модуля в JS API Lite Wearable нет; на часах пункт «Звук» не показывается.
- **Риск установки:** в собранном манифесте `minPlatformVersion: 24` (от `compatibleSdkVersion 6.1.1(24)` в `build-profile.json5`). Если на часах с HarmonyOS 5.1 уровень API ниже — пакет не встанет; тогда понижать `compatibleSdkVersion`.
- Не проверено до Previewer / часов: привязка числовых размеров в `style` без `px`, цвета строкой в `style`, шрифты нужных размеров и глифы («·»), свайп вправо внутри приложения против системного жеста выхода, `rotation` списка колёсиком.

## Приложение: конкретика по установке (собрано при исследовании)

Чтобы завтра не искать заново.

**Путь собранного пакета в проекте**

```
build/outputs/hap/debug/liteWearable/<имя>.hap
```

**Перенос на телефон**

Скопировать `.hap` в папку `/sdcard/haps/` на телефоне. Если папки `haps` в корне `/sdcard/` нет — создать вручную.

**Установка на часы**

1. Часы подключены к телефону по Bluetooth, Huawei Health открыт и видит часы.
2. Открыть «应用调测助手» / DevEco Assistant.
3. Раздел «应用管理» (управление приложениями) — там появится список `.hap` из папки `haps`.
4. Кнопка «安装» (установить) — пакет уходит на часы.
5. Иконка приложения появляется в списке приложений на часах.

**Где взять DevEco Assistant**

Пакет `com.huawei.deveco.assistant`. Источники: AppGallery, либо магазин Tencent (`sj.qq.com/appdetail/com.huawei.deveco.assistant`). Это обычный Android APK, привязки к Huawei-телефону в самом APK нет — но связка с часами идёт через Huawei Health, поэтому работоспособность на не-Huawei телефоне проверяется на этапе 0.

**Версия DevEco Studio**

Шаблон Lite Wearable присутствует в DevEco Studio начиная со старых версий и, по свежим источникам, доступен и в актуальных (для Lite Wearable создаётся проект «Lite Empty Ability», тип устройства — Lite Wearable, язык JS; шаблон ArkTS выбирать нельзя). Практические статьи 2025 года по轻量级智能穿戴 используют DevEco Studio 4.x.

**Проверено 2026-09-14:** в DevEco Studio 6.1.1.280 (Windows) шаблон **[Lite]Empty Ability** есть — архивная версия не нужна.

**Сборка и Java.** Шаг `LegacyGenerateLiteCode` вызывает `java` из PATH. На этом компьютере в PATH стоит заглушка `C:\Program Files (x86)\Common Files\Oracle\Java\javapath` от удалённой Java 8 → ошибка `could not open ...\jre-1.8\lib\amd64\jvm.cfg`. Решение: `JAVA_HOME = C:\Program Files\Huawei\DevEco Studio\jbr` и `%JAVA_HOME%\bin` в PATH раньше `javapath` (или удалить остатки Java 8). Проверено: одного `JAVA_HOME` недостаточно — сборщик берёт `java` из PATH. `javapath` стоит в **системном** PATH, а системный PATH идёт раньше пользовательского, поэтому правка только пользовательского PATH не поможет. Сборка из командной строки:

```
set JAVA_HOME=C:\Program Files\Huawei\DevEco Studio\jbr
set DEVECO_SDK_HOME=C:\Program Files\Huawei\DevEco Studio\sdk
set PATH=%JAVA_HOME%\bin;%PATH%
cd watch
"C:\Program Files\Huawei\DevEco Studio\tools\node\node.exe" "C:\Program Files\Huawei\DevEco Studio\tools\hvigor\bin\hvigorw.js" --mode module -p module=entry@default -p product=default -p buildMode=debug assembleHap --no-daemon
```

Пакет без подписи: `watch/entry/build/default/outputs/default/entry-default-unsigned.hap`.

Исходный порядок действий: поставить актуальную версию, открыть мастер создания проекта и посмотреть, есть ли в списке типов устройств **Lite Wearable**. Если его нет — скачать более раннюю версию из архива: <https://developer.huawei.com/consumer/cn/deveco-studio/archive/>

**Что осталось непроверенным**

- Точный набор режимов `@system.vibrator` на Fit 4 Pro — и главное, есть ли длительная вибрация на заданное время или только короткие импульсы (от этого зависит реализация вдоха).
- Комфортная частота импульсов на вдохе (`inhalePulseHz`).
- Наличие `setKeepScreenOn` в `@system.brightness` на этом устройстве.
- ~~Работает ли DevEco Assistant в связке с не-Huawei телефоном.~~ **2026-09-15:** DevEco Assistant видит часы через не-Huawei телефон и показывает UDID. Установка пакета ещё не проверена.
- Фактическая плавность CSS-анимаций в ArkUI.Lite на этом железе.

Все четыре пункта закрываются на живом устройстве, отдельного исследования не требуют.
